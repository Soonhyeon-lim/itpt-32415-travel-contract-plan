조회

DESCRIPTION

1
검토 필요동적 타이틀 · 패키지 탭 단독 개선 항목 ⑤

① 타이틀 — 여행계약서 딥링크로 진입한 경우 상단 타이틀을 "여행계약서 조회"로 표기(기본 "비회원 예약조회"에서 전환).

② 상품 탭 — 여행계약서는 패키지 상품만 해당하므로 호텔·항공 탭은 노출하지 않고 패키지 탭만 사용.

페이지 카피 아님 — 비회원 예약조회 페이지 재사용, redirectUri 컨텍스트를 읽어 타이틀·탭 구성을 함께 분기(이중 유지보수 회피).

⚠ 개발팀 검토 필요 — 컨텍스트 읽어 동적 전환하는 방식보다, 여행계약서 전용 진입 페이지(정적 shell)를 별도로 두는 편이 구현 효율적일 수 있음. 착수 전 협의 대상.

2
예약번호 자동주입

딥링크 파라미터(resCd)로 예약번호 자동 채움 → 고객은 이름 + 휴대폰번호만 입력. 세션 만료 우회 경로에서도 유지(ITPT-24104).

3
조회 방식

연락처로 조회 / 이메일로 조회 라디오. 예약 시 제공한 여행자 본인 정보 입력(예약자 ≠ 여행자 주의).

4
조회 성공 → 예약 상세 (현행)

조회에 성공하면 예약 상세로 이동. 여행계약서 팝업(SC-02)은 그 예약 상세 화면에서 노출되는 구조 — 계약서로 바로 가는 것이 아님.

현행 흐름 그대로이며 이번 개편에서 바꾸지 않음.

–
진입 규칙 · 데이터

비회원 전용(회원은 로그인 → 마이페이지 → 계약서). 로그인 페이지 하단 '비회원 예약조회' 버튼 라벨은 공용이라 미변경.
