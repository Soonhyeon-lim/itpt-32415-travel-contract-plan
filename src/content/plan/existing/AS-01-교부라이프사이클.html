AS-01

여행계약서 교부 라이프사이클

최초 교부 → D-2 확정 교부 → 재교부(조건부)까지, 한 예약에서 계약서가 몇 번 어떻게 나가는가.
교부상태 = 고객의 열람 여부(미교부 / 교부완료) — 동의와는 별개 상태값이다.

변경 사항 없음. 기존 로직 유지
  • ① 지상·항공 OK/OK 전환 시 최초(1차) 교부
  • ② 변경이 없어도 출발 D-2에 2차 교부 — 확정 계약서(단, 이후에도 변경될 수 있음)
  • ③ 재교부 요건(항목 변경) 발생 시 N+1차 교부 — 단, 고객이 직전 차수를 열람(교부완료)한 경우에만
  • ④ 교부상태가 미교부이면, 고객이 예약내역(예약 상세)에 진입하는 순간 여행계약서가 자동으로 팝업 노출 — 고객이 따로 버튼을 누르지 않는다. 그렇게 계약서가 호출·노출되면 BE에서 미교부 → 교부완료로 상태 전환된다. (현행 로직 — 이번 개편에서 바꾸지 않음)
⚠ ④가 이번 개편에 갖는 의미 — 비교 트리거의 실체

LG-01의 비교 트리거인 미교부 → 교부완료 전환은, 실제로는 고객이 예약내역에 들어와 계약서 팝업이 자동으로 뜨는 순간이다. 즉 고객의 능동적 클릭이 아니라 페이지 진입만으로 발동한다.
→ 비교가 예약내역 진입 응답 경로에 얹히므로, 동기 수행 시 계약서 팝업이 뜨는 속도에 직접 영향을 준다. 비동기(계약서 먼저 표시 · 변경 내역 탭만 로딩) 검토가 필요한 이유가 여기에 있다(성능 실측 후 판단).

재교부 요건 (담당자 판단 기준)

  • 상품 정보 변경 : 제목 · 브랜드 · 프로모션 · 테마 · 여행기간 · 최저행사인원 · 인솔자 · 가이드 · 포함사항 · 여행자보험 · 취소료 규정
  • 예약 정보 변경 : 인원 · 예약가 · 변동금액 전항목 · 현지합류 구분 · 대리점 · 여행자 이름 · 연락처 · 상품 이동
  • 상태 전환 : WT → OK (최초 1회)
  • 그 외 조건은 “재교부 필요” 상태 팝업만 (알림톡 X)

개발 확인 상태 — 미교부 구간

항목내용상태
(a) 미교부 구간 갱신 구현 방식같은 레코드 in-place update로 진행될 것으로 보임 — N차 폐기 후 재생성 아님. (b)가 “재알림 없음”으로 확정된 것과 정합(레코드 신규 생성 이벤트에 발송이 걸리는 방식이면 부정합)잠정확정
