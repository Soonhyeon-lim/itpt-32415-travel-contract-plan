여행계약서 교부 라이프사이클

교부·열람·동의 구분

교부는 고객에게 계약서를 제공하는 행위, 열람은 고객이 실제 내용을 확인하는 행위이다. 발송으로 교부완료되어도 고객은 미열람일 수 있다. 동의는 별도 상태로 관리한다.

세 교부 경로와 스냅샷 저장 기준

  • ① 허브·파트너포탈: 담당자가 이메일·알림톡·MMS 등으로 고객에게 계약서를 전달
  • ② 배치: 최초·D-2 등 자동 발송으로 계약서를 전달. D-2 차수 +1은 유지
  • ③ 고객 화면: 미교부 계약서가 FE 팝업에 실제 표시되면 교부와 열람이 함께 발생
  • ④ 각 경로의 교부완료 시 해당 계약서 데이터를 스냅샷으로 저장. 중간 수정 시 미저장
  • ⑤ 이미 교부된 동일 계약서의 후속 열람은 저장본 조회. 새 차수·스냅샷 생성 또는 덮어쓰기 없음
[개발 확인] 경로별 완료 이벤트·저장 데이터 연결

[개발 확인] 발송 요청·접수·성공 중 완료 판정 시점 및 FE 표시 완료 API 확인
[개발 확인] 발송 실패·SMS/MMS 대체 발송·중복 통지·저장 실패 복구와 차수 연결 확인
기획 기준: 발송 후 열람에도 교부 당시 데이터를 제공. 조회 중·실패는 변경 0건과 구분한다.

최초·D-2 발송과 후속 열람

  1. 최초 계약서 생성·발송

    지상·항공 OK/OK 조건의 최초 발송. 발송 교부완료 시 해당 계약서 스냅샷을 저장한다.

  2. D-2 차수 +1·발송

    직전 교부상태·변경 여부와 무관하게 차수 +1. 발송 교부완료 시 N차 스냅샷을 저장한다.

  3. 고객 열람

    이미 교부된 동일 계약서는 저장본을 조회한다. 후속 열람만으로 새 차수·스냅샷을 생성하거나 덮어쓰지 않는다.

  4. 이전 완료본 비교

    현재 차수를 제외한 가장 최근 이전 완료 스냅샷과 비교한다. 미열람 완료본도 포함하며 실제 미교부 차수는 건너뛴다.

일반 재교부의 차수 처리

직전 계약서 상태작업 데이터·차수 처리해당 차수 교부완료 시
교부완료 — 발송 완료 포함, 미열람 가능N+1차 준비, 미교부로 시작. 기존 완료 스냅샷은 변경하지 않음발송 또는 FE 직접 교부완료 시 저장. 가장 최근 이전 완료본과 비교
미교부 — 어느 경로로도 교부 미완료같은 미교부 차수의 작업 데이터 갱신. 완료 스냅샷 미생성발송 또는 FE 직접 교부완료 시 저장. 하나허브는 이전 완료본이 있으면 비교, 없으면 비교 대상 없음. 고객은 계약서만 표시
D-2는 일반 재교부와 차수 증가 조건이 다름

D-2는 직전 교부상태와 무관하게 차수 +1. D-2 세 가지 비교 사례 참조. [개발 확인] 경로별 완료 판정·상태 분기·중복 처리.

(b) 미교부 구간
갱신 시 재알림 여부		중간 변경에 따른 재알림 없음. 정기 자동 발송은 최초 + D-2이며, D-2 발송 시 현재 차수 +1확정
원천·M 갱신과 교부 스냅샷은 별개

중간 변경에는 저장하지 않고 세 경로의 교부완료 시 저장한다. 미열람을 미교부로 판단하지 않는다. 이미 교부한 값은 후속 조회에도 보존한다.
