LG-02

항목별 구현 로직

「개선 항목」IM-04의 ①~⑤와 같은 번호 — 각 항목을 무엇으로 구현하는가.

① 계약서 차수·변경 내역 표기 닷컴 Vue

  • 차수 표기 — 이 계약서가 몇 번째로 발행된 것인지(1차·2차…)를 계약서 상단에 표시. 이미 계약서 데이터에 들어 있는 발행 순번을 그대로 사용.
  • 변경 내역 데이터 — 여행 계약서가 새로 교부될 때, N-1차 · N차 계약서를 비교하여 달라진 항목만 추출·저장.
  • 상단 안내 문구 3가지 Case — 최초 교부 · D-2 교부 · 요건 변경 재교부 세 케이스에 따라 상단 안내 문구를 다르게 처리.
    • 최초 교부 → “다시”를 뺀 1차형 문구
    • D-2 교부 → 출발 확정 안내 문구 (변경 내역 없음)
    • 요건 변경 재교부 → “변경된 항목이 있는 경우 [변경 내역] 탭에서 확인해 주세요” 유도 문구 — 조건부 표현 고정(비교 0건이라 탭이 없어도 문구 정합)
  • 변경 내역 탭 — 저장된 변경 내역을 표(변경 항목 / 이전 내용 / 변경 내용)로 전 항목 노출. 요약·생략 없음.
  • 탭 노출 조건 — 변경 항목 0건이면 [변경 내역] 탭 미생성 → 현행 단일 화면 유지.

⚠ 아직 정할 것 — 변경 내역은 시스템 내부 항목 단위로 나오므로, 고객에게 보여줄 항목 이름(예: 상품명·여행기간·개인추가경비)과 보여주지 않을 항목을 따로 정해야 함.

② 개인추가경비 합산 한 줄 닷컴 Vue · 하나허브 OZ

  • 합산 금액 — 상품가 외 변동 항목(항공·호텔·지상·기타 + 매출할인 마이너스)을 전부 합산해 “개인추가경비 N원” 한 줄로 표기. 음수 허용.
  • 산술 검증 — Σ전 인원(상품가 + 개인추가경비) = 총 N인 경비 총액 (예약코드 전 인원 합 기준).
  • 노출 조건 — 변동 항목 건수 > 0일 때만 노출(금액 기준 아님). 0건이면 미노출, 1건 이상이면 합산 0원이어도 0원 노출.

⚠ 집계 소스 미확정 — 합산 소스를 계약서 API 확장으로 갈지 결제·예약 API 병행 호출로 갈지 확인 필요 → LG-04 개발 확인 ①(최우선).

④ 하나허브 여행계약서 교부내역 — 합산값 · 변경 내역 하나허브

  • 합산값 — ②와 동일한 합산 로직 공유(값 일치 보장).
  • 변경 내역 팝업 — LG-01에서 저장한 변경 내역을 조회해 표(변경 항목 / 이전 내용 / 변경 내용)로 렌더. 표 구성·항목명 매핑·노출 제외 규칙 전부 ①과 동일 적용, 하나허브에서 재비교 없음.
  • 노출 조건 — 변경 결과 0건이면 팝업 진입점 미노출(고객 화면과 동일).

하나허브 OZ 문서 양식은 미변경 — 여행계약서 교부내역 메뉴에만 표시 추가.

⑤ 여행계약서 조회 진입 페이지 검토 필요

  • 재사용 방식 — 기존 비회원 예약조회 페이지를 재사용, 진입 컨텍스트를 읽어 타이틀·상품 탭을 동적 전환(페이지 신규 카피 아님).
  • 승계 4조건 — ① 예약코드 자동주입 유지(이름+휴대폰, 세션 만료 경로 포함) ② 딥링크 컨텍스트로 타이틀 + 패키지 탭 단독(호텔·항공 탭 미노출) ③ 조회 성공 → 예약 상세로 이동(계약서 팝업은 예약 상세에서 노출 — 현행 흐름 유지) ④ 비회원 전용(회원은 로그인 → 마이페이지).

⚠ 개발팀 검토 필요 — 컨텍스트로 타이틀만 바꾸는 방식보다 여행계약서 전용 진입 페이지(정적 shell)를 따로 두는 편이 구현 효율적일 수 있음. 착수 전 협의 대상.
