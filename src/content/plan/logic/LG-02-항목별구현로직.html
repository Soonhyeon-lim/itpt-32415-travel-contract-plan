① 계약서 차수 · 발송 유형별 안내

  • 차수: 계약서 판 번호를 표시하고 완료 스냅샷과 연결
  • 저장: 세 경로의 교부완료 시 저장. 최초·재교부·D-2 공통. 중간 수정·후속 열람 시 미저장
  • 고객 Front: 차수·과거 완료본·변경 유무와 무관하게 계약서만 표시
  • 상단 문구: 최초 / D-2 / 변경 재교부 구분. D-2 이후 재발송 약속 및 변경내역 탭 확인 문구 제외
  • [현업 확인] D-2 발송 후 변경은 알럿만. 계약서 자동 생성·고객 별도 안내·새 교부 스냅샷 없음
  • 변경내역 탭·비교표·변경 0건 안내는 고객 화면에 제공하지 않음
  • 하나허브: 완료 스냅샷 간 비교와 17개 항목의 묶음·단독 표기 유지(상품·예약 데이터 정의표)
  • 비교 대상 없음·변경 0건·미교부·조회 실패는 하나허브에서 구분
  • [개발 확인] 고객 비교 데이터 미사용 및 응답 분리. 교부완료·저장 연계와 하나허브 조회 유지

② Front 여행경비 5개 항목 · 개인추가경비 합산

  • Front 순서: 총 N인 경비총액 / 1인 여행경비 / 상품가 / 유류할증료 / 개인추가경비 (각 N원)
  • 집계: 첫 줄은 예약 전체 여행자 합계, 나머지 네 줄은 조회한 여행자 1인 기준
  • 1인 여행경비 = 상품가 + QCH + 개인추가경비. 개인추가경비는 QCH 제외 22개 합계(TAX·할인·음수 포함)
  • BE: 여행자별 상품가와 항목별 금액 제공. 저장본 조회 시 당시 값 사용. 최종 원천·통화·집계 단위 확인
  • 개인추가경비 대상 0건이면 본문 줄 미노출, 대상이 있으면 0원도 표시. 하나허브 비교·OZ 기존 범위 유지

③ 일정표 선택관광 · 쇼핑 단순 표기

교통·숙박·식사와 같은 일정표 표시 방식으로 단순 안내한다. 닷컴 Vue·하나허브 OZ Report 모두 반영한다.

④ 하나허브 여행계약서 교부내역

  • 합산값: 선택한 완료 차수의 저장 금액으로 계산. 최신 원천값으로 과거 금액을 대체하지 않음
  • 변경 내역: 하나허브에서 17개 항목 비교 조회. 이전본이 없어도 보기 버튼 유지 및 “비교 대상 없음” 안내
  • 보기: 최초 행에도 버튼 제공. 미교부 / 비교 대상 없음 / 변경 0건 / 오류를 구분
  • 허브·파트너포탈 단순 조회는 미저장. 고객 발송은 교부 경로이며, 교부완료 시 저장
  • 조회 범위: 선택 차수 비교안을 화면 예시에 반영. 누적 이력 제공 여부는 추가 협의

⑤ 여행계약서 조회 진입 페이지

  • 재사용 방식 — 기존 비회원 예약조회 페이지를 재사용, 진입 컨텍스트를 읽어 타이틀·상품 탭을 동적 전환(페이지 신규 카피 아님)
  • 승계 4조건 — ① 예약코드 자동주입 유지(이름+휴대폰, 세션 만료 경로 포함) ② 딥링크 컨텍스트로 타이틀 + 패키지 탭 단독(호텔·항공 탭 미노출)
  • ③ 조회 성공 → 예약 상세로 이동(계약서 팝업은 예약 상세에서 노출 — 현행 흐름 유지) ④ 비회원 전용(회원은 로그인 → 마이페이지)
  • ⚠ 개발팀 검토 필요 — 컨텍스트로 타이틀만 바꾸는 방식보다 여행계약서 전용 진입 페이지(정적 shell)를 따로 두는 편이 구현 효율적일 수 있음. 구현 로직 확인 필요
