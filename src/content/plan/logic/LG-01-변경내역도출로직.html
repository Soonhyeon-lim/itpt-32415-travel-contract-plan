교부완료 데이터 저장 및 하나허브 비교

저장: 허브·파트너포탈 발송 / 배치 / FE 직접 교부의 완료 시 데이터 저장. 중간 변경·동일 계약서 후속 열람 시 미저장
비교: BE가 이전·현재 완료본에서 하나허브 조회용 17개 항목을 비교. 새 내부 필드는 자동 포함하지 않음

기존 M 68개 일괄 비교는 적용하지 않는다. 신규 스냅샷 필드와 매핑은 개발 확인 대상이다.

데이터 조달 및 API 역할

  • 고객 계약서: 기교부 건은 저장본 조회, 미교부 건은 FE 직접 교부 대상·데이터 제공. 변경내역 미노출
  • 저장·비교: 각 경로의 교부완료 시 저장. 하나허브에서 이전·현재 완료본 비교 결과 조회
대상 / 데이터구분내용
고객 / 계약서표시 데이터해당 차수에서 발송·표시한 계약서와 스냅샷 연결. 후속 열람도 당시 값 제공 [개발 확인]
하나허브 비교비교 조회하나허브에 이전본 유무·비교 차수·상태·이전값·변경값 제공. 고객 응답 분리 방식은 개발 확인

구분내용
■ Back-End
트리거허브·파트너포탈 발송 / 배치 / FE 직접 교부의 완료 시점
[개발 확인] 경로별 완료 이벤트·상태·저장 연계. 조회 진입·생성·동의·후속 열람은 저장 트리거가 아님
시점 근거고객에게 교부한 데이터를 해당 차수에 보관. 후속 열람도 당시 값 제공. 중간 수정 시 미저장
비교 입력현재 차수 이전의 최근 교부완료 스냅샷과 비교. 미열람 완료본도 포함. 실제 미교부 차수는 제외
처리정의한 필드만 비교해 이전값·변경값 조회. 최신 원천 재조회로 과거 값을 대체하지 않음
저장첫 완료부터 비교 대상 데이터 전체 저장. 이후 같은 완료본은 불변. 테이블·연결키·중복 방지 방식은 개발 확인
■ 하나허브 비교 조회 응답
응답 필드이전 완료 스냅샷 유무, 비교 차수·식별 정보, 이전값·변경값, 조회 상태. API 명칭·구조는 개발 협의
화면 활용 (1)
변경 내역 표		BE는 프로모션·날짜·인원·22개 변동금액을 분리 제공. 하나허브는 17개 항목 표시 규칙에 따라 묶어서 표현
고객 Front
미노출		고객은 이전 완료본 유무와 무관하게 계약서만 표시. 변경내역 탭·비교표·탭 안내 미노출
최초 / D-2D-2 차수 +1, 발송 교부완료 시 저장. 하나허브는 이전 완료본과 비교. 고객 첫 열람 여부로 비교 대상을 바꾸지 않음

D-2 세 가지 비교 사례

D-2 차수 +1 · 발송 교부완료 시 저장

하나허브는 이전 완료본과 비교한다. 고객은 계약서만 표시한다. 미열람 완료본도 비교에 포함하며 실제 미교부 차수는 건너뛴다.

  • ① N-1차 완료본 있음(미열람 포함): N차 교부완료·저장 후 하나허브에서 N-1차와 비교. 변경 0건도 구분.
  • ② 과거 완료 스냅샷 없음: N차 교부완료·첫 스냅샷 저장 후 하나허브에 비교 대상 없음 안내.
  • ③ N-2차 완료, N-1차 실제 미교부: N차 교부완료·저장 후 N-2차와 비교. 미열람 완료본은 포함.
  • 고객 Front는 모든 사례에서 변경내역 탭·비교표 없이 계약서만 표시한다.

③중복·실패 복구[개발 확인] 복수 채널·재전송·후속 열람 중복 방지, 발송/저장 실패·대체 발송·복구 및 상태 일관성
④최초·배포 전 이력적용 후 교부완료부터 저장, 배포 전 소급 없음. 기교부·스냅샷 없음 / 미교부 / 조회 실패 구분 [개발 확인]
