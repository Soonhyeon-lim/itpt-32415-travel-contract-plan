IM-04

개선 항목 상세

① 계약서 차수·변경 내역 표기

  • 상단 문구 — 계약서 상단에 [N차 여행계약서]와 함께 발송 상황별 안내 문구 — 최초 발송 / 출발 확정 / 변경 재교부. (직전이 미교부라 교부이력이 없는 재발송은 최초 발송 문구를 재사용.)
  • 변경 재교부 문구 — “변경된 항목이 있는 경우 [변경 내역] 탭에서 확인해 주세요”로 유도. 상단에 변경 항목은 나열하지 않음. 조건부 표현이라 비교 결과가 0건이라 탭이 없어도 문구와 어긋나지 않음.
  • 변경 내역 탭 — 직전 계약서 대비 바뀐 항목이 있을 때만 [계약서 / 변경 내역] 탭이 생기고, 무엇이 무엇으로 바뀌었는지 표로 표기. 내용 변경 없이 차수만 바뀌면 탭 미노출.

→ 고객이 “또 왔네”가 아니라 “이게 바뀌어서 왔구나”로 읽히게 하는 것이 목적.

② 개인추가경비 합산 한 줄

상품가 외에 추가로 낸 금액을 “개인추가경비 N원” 한 줄로 전부 합산해서 표기.

여행계약서 여행경비 표기 — 1인 예약 예시
총 1인 경비총액774,400 원
1인 여행경비774,400 원
개인추가경비312,400 원
1인 여행경비(774,400) = 판매상품가(462,000) + 개인추가경비(312,400) — 이미 포함
  • 매출할인 포함 — 마이너스 금액도 합산 → Σ전 인원(상품가 + 개인추가경비) = 총 N인 경비 총액. 매출 할인만 있으면 음수로 그대로 표기.
  • 집계 단위 주의 — 총 N인 경비총액 = 예약코드 전 인원 합 / 1인 여행경비·개인추가경비 = 조회한 여행자 1인 값. 1인 여행경비가 개인추가경비를 이미 포함하므로 두 줄을 더하면 중복이고, 인원 2명 이상이면 1인 여행경비 ≠ 총액(1명일 때만 일치) — 산술 검증은 전 인원 데이터 기준.
  • 노출 조건 — 변동 항목 0건일 때만 줄 미노출. 항목이 있으면 합산 0원이어도 개인추가경비 0원 노출(예: 선택관광 + 매출할인 상계). 세부 상품명·건수는 표시 안 함(한 줄).

③ 일정표 선택관광·쇼핑 단순 표기

여행계약서 내 ‘선택관광 / 쇼핑’ 필드를 추가하여, 일정표에 선택관광·쇼핑이 있다는 사실을 미리 표기.

교통·숙박·식사를 일정표에 표시하는 것과 같은 방식.

④ 하나허브 여행계약서 교부내역 — 개인추가경비 합산값 · 변경 내역

  • As-Is — 고객이 보는 “개인추가경비 N원”과 같은 값을 상담원이 바로 확인할 방법이 없음(현재 불가).
  • To-Be — 하나허브 여행계약서 교부내역에도 같은 합산값을 표시하고, 변경 내역은 별도 팝업으로 확인.
  • 변경 내역 팝업 — 고객 화면(①)의 ‘변경 내역’ 탭과 같은 것을 그대로 사용(같은 데이터·같은 표 No / 변경 항목 / 이전 내용 / 변경 내용).

→ 개인추가경비는 개선 ②와, 변경 내역은 개선 ①과 반드시 같은 값.

⑤ 여행계약서 조회 진입 페이지 검토 필요

  • As-Is — 알림톡 “여행계약서 확인”을 눌렀는데 (앱 없음/로그인 안 됨) 로그인 페이지를 거쳐 “비회원 예약조회” 화면으로 도착. 제목이 “예약조회”라 “여기가 맞나?” 하고 이탈(CS 1위 진입 장벽 잔여분).
  • To-Be — 계약서로 들어온 고객에게는 화면 제목을 “여행계약서 조회”로 표시, 패키지 상품만 해당하므로 호텔·항공 탭 없이 패키지 탭만 노출.
  • 포인트 3가지 — ① 예약번호 자동 채움(고객은 이름·휴대폰만 입력) ② 계약서로 들어온 경우에만 제목·탭 전환 ③ 조회 성공 → 예약 상세로 이동(계약서 팝업은 그 화면에서, 현행 그대로).

닷컴 직접예약 건 D-2 발송 포함 확인 항목

  • 현행 — 닷컴 직접예약 건은 최초 알림톡이 나가지 않음(예약내역에서 바로 확인).
  • 요구사항 — 이 건들도 출발 2일 전 최종 확정본 발송 대상에 포함 → 모든 고객이 출발 전 확정된 계약서 수신. 새 기능이 아니라 기존 발송 포함 여부 확인 건이라 개선 번호에서 제외.
